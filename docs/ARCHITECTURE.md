# Envo Desk — архитектура

Предметная модель и продуктовые решения — в [DOMAIN.md](DOMAIN.md). Здесь только
техническая часть: из чего собрано, где работает, как развёртывается.

## 1. Что заменяем

Пять Cowork-рутин, где логика лежит текстом внутри промпта и выполняется сессией модели:
часовой прогон продаж и писем, догон брошенных корзин, ценовая лестница, тест сети,
навык расчёта цен. Проблемы этой схемы:

- логика в тексте промпта — нет версий, нет diff, нет отката;
- у облака нет сети до `api.tickets.yandex.net`, `script.google.com`, `api.telegram.org`;
- модель в критическом пути: отправка письма, проверка «писали ли раньше», отметка факта;
- состояние в Google Sheets — без транзакций и уникальных ключей, дедуп по соглашению;
- частота прогонов продиктована ценой сессии, а не смыслом;
- секреты открытым текстом в промптах.

## 2. Размещение

```
Виртуалка (РФ, 2 vCPU / 2–4 ГБ)              Mac
├ Python-ядро + планировщик                  ├ SwiftUI-приложение
├ Postgres + файлы квитанций            ◀──▶ ├ клиент, сгенерированный из OpenAPI
└ FastAPI за TLS, вход по логину             └ воркер: съём упрямых страниц через WebKit
                     │
     Афиша · Microsoft Graph · Telegram · RSS · ЦБ · сайты поставщиков
```

Ядро живёт на сервере, потому что Mac спит, а мониторинг не должен. Mac при этом не только
интерфейс: с домашнего адреса страницы отдаются охотнее, чем датацентровому IP, поэтому
приложение работает ещё и съёмщиком цен для площадок, которые закрываются от автоматики.

База с персональными данными покупателей стоит у российского хостера — этого требует закон
о локализации, и попутно это лучший маршрут до Афиши.

## 3. Стек

**Python 3.11 на сервере, SwiftUI на Mac.**

| Слой | Чем |
|---|---|
| API | FastAPI + uvicorn, OpenAPI отдаёт схему клиенту |
| База | Postgres 15, схема в [`db/schema.sql`](../db/schema.sql) |
| Планировщик | APScheduler в том же процессе |
| Сеть | httpx, для CRM — stdlib, чтобы клиент не тянул зависимостей |
| Парсинг | selectolax, JSON-LD из разметки страниц |
| Почта | Microsoft Graph через msal |
| Вход | argon2id, TLS, лимит попыток |
| Клиент | SwiftUI, модели из OpenAPI |

Python выбран не за скорость — здесь её негде тратить — а за количество интеграций: Афиша,
Graph, Telegram, RSS, парсинг, ЦБ, xlsx. И существующий проверенный код против CRM Афиши
переносится почти как есть. Ранняя ставка на Swift держалась на упаковке в один `.app` без
рантайма; когда ядро уехало на Linux, этот довод отпал.

## 4. Модули ядра

```
envo/
  afisha.py     — клиент CRM: подпись, ретраи, нормализация ответов. Только чтение
  money.py      — каналы продаж, себестоимость, волны маржи, P&L события
  names.py      — обращение по имени, склонение числительных
  normalize.py  — склейка клиентов, алиасы категорий
  ingest.py     — заказы и билеты в базу, идемпотентно
  feed.py       — лента новостей из открытых RSS агрегаторов
  pricewatch.py — розничные цены поставщиков
  mailer.py     — очередь писем, Graph, дедуп
  inbox.py      — входящие, темы, черновики ответов
  scheduler.py  — задачи, догон пропущенного, одна копия
  api/          — FastAPI: роуты, авторизация, схемы
```

Модули не вызывают друг друга. Обмен через таблицу `events_log`: `order.created`,
`price.changed`, `rate.changed`, `step.closed`, `feed.matched`. Правило подписывается на
сообщение — новое поведение добавляется правилом, а не правкой модулей.

## 5. Надёжность

- **Идемпотентность.** `tickets(order_id, afisha_id)` и `letters(kind, ref_id)` —
  первичный ключ и уникальный индекс. Повторный прогон ничего не дублирует, а повторное
  письмо клиенту физически невозможно — это гарантия схемы, а не аккуратности кода.
- **Окна сканирования** с запасом: продажи 3 дня, корзины 30. Пропущенный прогон
  догоняется следующим.
- **Одна копия задачи** — блокировка в базе.
- **Стоп-кран** — тумблер «ничего не отправлять»: письма остаются в очереди со статусом `held`.
- **Внешний сторож** — пинг после каждого успешного прогона. Молчание Telegram иначе
  неотличимо от «нет продаж».
- **Бэкап** — `pg_dump` по расписанию плюс файлы квитанций, на шифрованный носитель.

## 6. Вежливый съём данных

Порядок от надёжного к хрупкому: официальный API → `sitemap.xml`, RSS и JSON-LD разметка →
вежливый запрос к публичной странице (`robots.txt`, не чаще раза в N часов, `ETag`, кэш,
backoff на 429 и 503, честный User-Agent) → человек в цикле через Mac-воркер.

Капчу не решаем, отпечаток браузера не подменяем, прокси для обхода банов не крутим:
помимо правил площадок, такие схемы ломаются молча и именно тогда, когда за ними не смотрят.

## 7. Безопасность

- Секреты только в `/etc/envo/env` с правами 600, в репозитории — `.env.example`.
- **При миграции ротировать** пароль CRM, секрет Apps Script и токен Telegram-бота: они
  лежали открытым текстом в промптах рутин и прошли через логи сессий.
- Вход по логину и паролю, argon2id, TLS, лимит попыток. Схема `users` — на вырост.
- Квитанции и персональные данные попадают в бэкап, поэтому бэкап шифрованный.
- `audit` пишет, кто и что сделал, включая ручные действия.

## 8. Фазы

| Фаза | Объём | Готово, когда |
|---|---|---|
| **0. Каркас** | схема, клиент CRM, экономика, склейка, тесты | данные за 30 дней сходятся с листами Sheets |
| **1. Лестница** | наблюдение за ступенями, Telegram | сутки параллельно: те же счётчики и алерты |
| **2. Продажи** | ингест, возвраты, сводки | трое суток параллельно, сводки совпадают |
| **3. Почта** | Graph, очередь, подтверждение → авто | 20 писем без дублей и промахов |
| **4. Корзины** | машина состояний, окна, потолки | неделя без писем тем, кто уже купил |
| **5. Рынок** | лента, цены поставщиков, Mac-воркер | лента даёт находки, цены обновляются |
| **6. Закупка и клиент** | покупки, остатки, карточка клиента | прибыль считается от себестоимости |
| **7. Приложение** | SwiftUI-клиент, развёртывание, сторож | перезагрузка сервера — всё поднялось само |

## 9. Риски

| Риск | Ответ |
|---|---|
| Telegram или Graph не видны с виртуалки | проверка доменов при развёртывании; Telegram уходит на Mac-воркер |
| CRM меняет формат | `raw` в jsonb, нормализация на входе, алерт на незнакомое поле |
| Датацентровый IP ловит блоки | Mac-воркер для упрямых площадок |
| Дубль письма клиенту | уникальный индекс плюс проверка «Отправленных» |
| Письма в спам | SPF, DKIM, DMARC, свой темп |
| Потеря базы | `pg_dump` и внешняя копия; Афиша остаётся восстановимым источником |
| Проект на одном человеке | всё в git, развёртывание скриптом, никакой магии в ручных шагах |
